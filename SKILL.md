# Using ngiab-rs

`ngiab-rs` runs a NextGen data folder through **bmi-driver** (the catchment models) and then
**rs-route** (channel routing), and can plot the results. As an agent, always use the headless
`--auto` mode: the default mode is an interactive full-screen TUI that you can't drive.

## Data folder layout

A data folder is usually made by NGIAB_data_preprocess and lives under
`~/ngiab_preprocess_output/<run>/`. The first line of `~/.ngiab/preprocessor` names that parent folder.

```
<data>/
  config/realization.json     # models, period, output_root, output format
  config/*.gpkg               # hydrofabric (divides, flowpath-attributes with USGS gage ids)
  config/cat_config/...       # per-catchment init configs ({{id}} templates in realization.json)
  forcings/                   # forcing file(s)
  outputs/                    # bmi-driver writes output_root (default outputs/bmi-driver or outputs/ngen)
  outputs/troute/*.nc         # rs-route output
  eval/                       # evaluation files (never deleted by ngiab-rs)
  .ngiab-rs/stage/            # generated by local runs, wiped every run; don't edit
```

## Running

```sh
ngiab-rs <data> --auto [-j N] [-b local|docker|podman] [--no-routing] [--image IMAGE]
```

- It prints preflight checks to stderr, one per line, with `✓` ok, `ℹ` info, `⚠` warn or `✗` fail.
  Any `✗` means it doesn't run and exits 1. Read the fail line: it names the fix.
- It then runs bmi-driver, then rs-route (skipped by `--no-routing`, or if the realization's
  output format isn't csv). It exits 0 on success and non-zero if any step fails.
- `--auto` never prompts and never offers installs. If outputs already exist, it doesn't delete them.
- `-j` defaults to all CPUs. On shared machines pass a smaller value.
- For long runs, start it in the background and poll the log. Runs take from seconds (one
  catchment, days) to hours (100k catchments, years).
- If a data folder is named `self`, `models`, `backend` or `run`, write `./models` or use
  `ngiab-rs run models --auto`.

## Choosing a backend

The default is the first usable of local, docker, podman. Check what's usable with
`ngiab-rs backend list`. It prints each backend with `available`, `not installed`, `not running` or
`unsupported` and the reason.

| backend | when to use | requirements |
| --- | --- | --- |
| `local` | Linux x86_64 with glibc ≥ 2.34. Fastest, no containers. | `bmi-driver` and `rs-route` on PATH (or `~/.cargo/bin`), and model files in `~/.ngiab/container` (`ngiab-rs models update`) |
| `docker` / `podman` | everywhere else, or when local isn't set up | a running runtime. The image `docker.io/joshcu/ngiab-rs:<binary version>` is pulled on first use |

On local, container paths in configs (`/dmod/...`, `/ngen/ngen/extern/...`, `/data/...`) are mapped
automatically. **Don't edit the user's configs to "fix" these paths.** The user's `config/` is never
modified. The one exception is when bmi-driver's "add these mappings?" prompt is accepted interactively;
`--auto` never accepts it.

Unsupported everywhere: Python BMI modules (`bmi_python`) and SUMMA. Preflight fails on them. Local
LSTM output may differ slightly from docker on hosts with a much newer glibc (libm differences), which
is expected.

## Setup and maintenance commands

```sh
ngiab-rs --version
ngiab-rs self update [--check] [--version V] [-y]   # --check: exit 0 up to date, 10 update available
ngiab-rs models status                               # installed / backup / newest model bundle, glibc check
ngiab-rs models update [-y] [--version models-YYYY.MM.DD] [--file TAR] [--force] [--check]
ngiab-rs models revert [-y]                          # swap container <-> container.bak (twice = redo)
ngiab-rs backend list
ngiab-rs backend install docker|podman|local         # runs the installer; interactive, may use sudo
```

- `models` commands only do anything on Linux x86_64. They use a lock, so don't run two at once.
- `backend install` and the installers can run `sudo` and package managers. **Ask the user before
  running them.** Installing from scratch:
  `curl -LsSf https://github.com/JoshCu/ngiab-rs/releases/latest/download/install.sh | sh -s -- --backends docker -y`
  (`-y` accepts sudo prompts, so only use it with the user's consent).
- `self update` refuses inside a container and for cargo-installed builds.

## Files ngiab-rs owns

- In `~/.ngiab` (`$NGIAB_HOME` overrides it), only `container/`, `container.bak/`, `container.new/`,
  `container.tmp/`, `install.json` and `.lock`. Everything else in `~/.ngiab` belongs to
  NGIAB_data_preprocess. **Never delete it.**
- UI state is in `<config dir>/ngiab-rs/state.json`.

## Environment variables

`NGIAB_RS_BACKEND`, `NGIAB_RS_IMAGE`, `NGIAB_HOME`, `NGIAB_RS_REPO` (fork testing), `GITHUB_TOKEN`
(avoids GitHub API rate limits for `self update` / `models update`), and `OMP_NUM_THREADS` (set to 1 for
local bmi-driver if unset).

## Troubleshooting from preflight lines

| fail line | fix |
| --- | --- |
| `model files not installed` | `ngiab-rs models update`, or use `-b docker` |
| `not in model bundle …` | the realization needs a library the bundle lacks: `models update`, or the model is unsupported |
| `glibc X < 2.34` | use `-b docker` or `-b podman` |
| `Python BMI models are not supported` | the realization uses `bmi_python`; it can't run with ngiab-rs |
| ldd `not found` (e.g. SUMMA) | the model is unsupported |
| docker/podman `not running` | start the daemon (`systemctl start docker`, open Docker Desktop, `podman machine start`) |
